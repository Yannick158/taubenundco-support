Tauben & Co — Anleitung (Vorschau)

Einen eigenen Server einrichten

Stand: 23. Oktober 2026

English version below

Vorschau · kommt bald

Das Paket für den eigenen Server wird gerade gebaut. Diese Seite zeigt, was vorgesehen ist und was du vorbereiten kannst. Es gibt noch keinen Download und keine Befehle zum Abtippen; sobald das Paket getestet ist, wird die Seite vervollständigt.

Wozu ein eigener Server?

Der Pi schiebt seine Erkennungen und Aufnahmen auf einen Server. Dort liegen die Daten sicher, dort entstehen die Rückblick-Videos, dort werden Meldungen verschickt, und von dort holt sich die App alles, auch von unterwegs. Du musst dafür kein Loch in dein Heimnetz machen: Der Pi geht nach draußen, niemand geht hinein. Ein Server kann mehrere Standorte tragen.

Was du brauchst

  • Einen kleinen Server. Ein gemieteter virtueller Server oder ein Rechner zu Hause mit erreichbarer IP-Adresse. Für Daten und Videos sind etwa 2 GB Arbeitsspeicher und ein Prozessorkern ein Anfang; für die Videos ist mehr besser. Plane Speicherplatz für die Aufnahmen ein (ein einzelner Standort erzeugt grob ein Gigabyte pro Tag, wenn nichts ausgedünnt wird).
  • Eine öffentliche IPv4- oder IPv6-Adresse und die Möglichkeit, die Ports 80 und 443 (Webseite) sowie einen weiteren Port für den Pi (vorgesehen: 2200) freizugeben.
  • Eine Domain oder Unterdomain, die auf den Server zeigt, am besten mit Platzhalter-Eintrag, damit jeder Standort eine eigene Adresse bekommt.
  • Docker mit Docker Compose auf dem Server.
  • Eine E-Mail-Adresse für das Zertifikat (Let’s Encrypt).
  • Etwas Erfahrung mit Linux auf der Kommandozeile. Das Paket soll die Arbeit klein halten, ersetzt aber nicht den Umgang mit einem Server.

Die Schritte

  1. Server und Domain vorbereiten

    Server mieten oder bereitstellen, Docker installieren, die Domain auf die IP-Adresse zeigen lassen. Die Absicherung des Rechners selbst (Updates, Firewall, Anmeldung nur per Schlüssel) bleibt deine Sache.

  2. Das Paket holen

    Das Serverpaket tauben-server kommt als Release auf GitHub. Es ist ein Docker-Compose-Paket: Webserver mit automatischem Zertifikat, die Webseite der Station, ein Wächter für die Anmeldung, ein Dienst für die Verbindung vom Pi und ein Arbeitsdienst für die regelmäßigen Aufgaben.

  3. Einrichten

    Ein Einrichtungsbefehl fragt nach der Domain und deiner E-Mail-Adresse, erzeugt die Schlüssel (Anmeldung, Browser-Meldungen) und prüft am Ende, ob der Server von außen erreichbar ist. Er legt auch die Beschreibung an, an der die App erkennt, dass hier ein Tauben-&-Co-Server läuft.

  4. Standort anlegen

    Du legst einen Standort an (Name, Kurzname, Sprache, ungefähre Position) und setzt sein Passwort. Dabei bekommst du den Koppelcode für den Pi: Pi installieren.

  5. Pi koppeln

    Der Pi meldet sich mit dem Koppelcode an, erzeugt seine Schlüssel selbst und hinterlegt nur den öffentlichen Teil auf dem Server. Danach zeigt der Server, dass sich der Pi gemeldet hat.

  6. App verbinden

    In der App wählst du „Tauben & Co Station“, trägst die Adresse deines Servers ein, wählst den Standort und gibst sein Passwort ein.

Betrieb

  • Updates: Das Paket bekommt neue Versionen als Release; ein Update-Befehl holt sie.
  • Sicherung: Die Daten liegen in Docker-Volumes. Ein Befehl zum Sichern ist vorgesehen; zusätzlich empfehlen wir eine Sicherung des ganzen Servers.
  • Videos: Sind ein zuschaltbarer Teil. Sie brauchen Rechenzeit, auf sehr kleinen Servern dauern sie.
  • Optional: Die zweite Meinung (Perch) und die automatische Erzeugung fehlender Zeichnungen (dafür braucht es einen eigenen Schlüssel von dir) sind abschaltbar.

Was der Server speichert

Pro Standort die Erkennungen (Art, Zeitpunkt, Trefferwert), die Aufnahmen vom Pi samt Spektrogrammen, die Falsch-Markierungen, die erzeugten Videos, die Geräte, die du mit der App angemeldet hast (nur als Prüfsumme des Tokens), und Nachrichten zwischen verbundenen Geräten (30 Tage). Aufnahmen können leise Gesprächsfetzen enthalten. Betreiber dieses Servers bist du; für ihn gelten deine eigenen Pflichten. Was die App mit deinem Server austauscht, steht in der Datenschutzerklärung, Abschnitt 3.6.

Was noch nicht dabei ist

  • Meldungen direkt auf das Handy (Apple und Google verlangen dafür eigene Schlüssel und einen Vermittler): Zunächst gibt es Browser-Meldungen; die App holt neue Funde beim Öffnen und im Hintergrund selbst ab.
  • Ein Weg, auf dem du die Verbindung ganz ohne Befehle einrichtest.

Tauben & Co — guide (preview)

Set up a server of your own

Last updated: 23 October 2026

Deutsche Fassung oben

Preview · coming soon

The package for your own server is being built right now. This page shows what is planned and what you can prepare. There is no download yet and no commands to type; once the package has been tested, the page will be completed.

Why a server of your own?

The Pi pushes its detections and recordings to a server. That is where the data is kept safe, where the review videos are made, where notifications are sent from, and where the app gets everything, also when you are out. You do not have to punch a hole into your home network: the Pi reaches out, nobody reaches in. One server can carry several locations.

What you need

  • A small server. A rented virtual server or a computer at home with a reachable IP address. For data and videos about 2 GB of memory and one processor core are a start; for the videos more is better. Plan storage for the recordings (a single location produces roughly a gigabyte a day if nothing is thinned out).
  • A public IPv4 or IPv6 address and the ability to open ports 80 and 443 (website) plus one more port for the Pi (planned: 2200).
  • A domain or subdomain pointing at the server, ideally with a wildcard record so that every location gets an address of its own.
  • Docker with Docker Compose on the server.
  • An e-mail address for the certificate (Let’s Encrypt).
  • Some experience with Linux on the command line. The package is meant to keep the work small, but it does not replace knowing your way around a server.

The steps

  1. Prepare server and domain

    Rent or provide the server, install Docker, point the domain at the IP address. Securing the machine itself (updates, firewall, key-only login) remains your job.

  2. Get the package

    The server package tauben-server will come as a release on GitHub. It is a Docker Compose package: a web server with automatic certificate, the station’s website, a gatekeeper for sign-in, a service for the connection from the Pi and a worker for the regular jobs.

  3. Set up

    A setup command asks for the domain and your e-mail address, generates the keys (sign-in, browser notifications) and finally checks that the server is reachable from outside. It also creates the description by which the app recognises that a Tauben & Co server is running here.

  4. Add a location

    You add a location (name, short name, language, approximate position) and set its password. In doing so you get the pairing code for the Pi: Install the Pi.

  5. Pair the Pi

    The Pi reports in with the pairing code, generates its keys itself and leaves only the public part on the server. Afterwards the server shows that the Pi has reported in.

  6. Connect the app

    In the app you choose “Tauben & Co station”, enter your server’s address, choose the location and enter its password.

Operation

  • Updates: new versions of the package come as releases; an update command fetches them.
  • Backup: the data lives in Docker volumes. A backup command is planned; we also recommend a backup of the whole server.
  • Videos: an optional part. They take processing time and on very small servers they are slow.
  • Optional: the second opinion (Perch) and the automatic creation of missing drawings (that needs a key of your own) can be switched off.

What the server stores

Per location: the detections (species, time, confidence), the recordings from the Pi together with spectrograms, the wrong-markings, the videos made, the devices you have signed in with the app (only as a checksum of the token) and messages between connected devices (30 days). Recordings can contain faint scraps of conversation. You are the operator of this server, and your own duties apply to it. What the app exchanges with your server is in the privacy policy, section 3.6.

What is not included yet

  • Notifications straight to the phone (Apple and Google require keys of their own and an intermediary for this): at first there are browser notifications; the app itself fetches new finds when you open it and in the background.
  • A way to set up the connection entirely without commands.
